fix: expired session no longer breaks every sync

Sync reported "JWT expired" once for every table, which read as a broken app.

Not a Supabase problem and not a key problem: the anon key in .env.local is
valid to 2036. Supabase access tokens last one hour, and
`supabase.auth.getSession()` returns the cached token without validating it. The
library's background auto-refresh only runs while the document is visible, so
closing the tab or locking a phone was enough to come back to a token that had
been dead for hours -- every request then 401'd, one error per table.

- getFreshSession() refreshes the access token when it is within 120s of expiry,
  rather than discovering it is dead on the first failed request
- the slack is deliberate: a sync touches nine tables, so a token that was valid
  at the start can expire part way through
- sync resolves the session through it, so the nine "JWT expired" errors become
  either a successful sync or one honest message
- refresh on window focus and on returning to the tab, which closes the window
  in practice rather than relying on the library's visibility-gated timer
- when the refresh token itself is rejected, sign out locally so the app stops
  showing a session it cannot use, and say so in Arabic instead of returning the
  raw Supabase message
