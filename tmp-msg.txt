fix: migrate via a new database, since Dexie cannot retype a primary key

Sync failed on every table with:

  UpgradeError Not yet support for changing primary key

Dexie is unable to change a primary key on an existing store, so declaring v7
with string keys could never upgrade an install that already existed on v6.
The version bump itself was unsatisfiable.

The app now opens a new database, `CoachOpsDB_v7`, and
migrateFromLegacyDb() copies the old rows across on first load:

- opens the previous `CoachOpsDB`, reads every table, closes it
- assigns a fresh UUID per row and remaps every foreign key, including the
  player ids nested inside lineup slots, substitutes and scorers
- writes the results into the new database in one transaction
- records a flag in localStorage so it never runs twice

deleteLegacyDb() is exported to drop the old database once the copy is
verified; it is intentionally not called automatically, so a failed or partial
migration can never destroy the original data.

Behaviour for the common case is unchanged: a brand new install has no legacy
database, finds nothing to copy, and starts empty.
