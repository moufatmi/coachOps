fix: rewrite the id migration to widen columns before remapping

The previous script failed with:

  42804 column "session_id" is of type bigint but expression is of type uuid

It assigned a fresh UUID into columns that were still bigint. A UUID cannot be
stored in a bigint column at all, so remapping first and retyping after can
never work.

The corrected order goes through text, which is the only type that can hold both
an old integer and a new uuid string:

  1. drop foreign keys (they block type changes)
  2. snapshot old id to new uuid into temp mapping tables
  3. widen every id and FK column from bigint to text
  4. remap ids, FKs, and the player ids nested in lineup slots,
     substitutes and scorers
  5. narrow text back to uuid, which now succeeds because the values are uuid
     strings
  6. restore the foreign keys

Still a single transaction, so a failure leaves the schema untouched.
