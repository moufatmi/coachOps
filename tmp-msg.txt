fix: sync both ways so a second device sees the first device's work

Reported symptom: signing in on a second device showed none of the changes
made on the first, even though the rows were present in Supabase.

Root cause was that sync only ever pushed. On sign-in the app pushed its local
database and never asked for anything, so a device that had not synced before
had nothing to send and nothing to fetch. The data existed on the server; the
client simply never requested it. This was a client-side bug, not a Supabase
configuration problem, so no schema change is needed.

Changes:

- syncNow() reconciles in both directions: pull first, then push. Pulling
  before pushing is what lets a fresh device adopt existing rows instead of
  treating its empty local database as the whole truth.
- Sign-in now runs syncNow() rather than pushNow().
- Reconnecting (the `online` event) also runs a full reconcile, since that is
  the likeliest moment to be holding new work from elsewhere.
- Focusing the tab or returning to it triggers a reconcile, which is how a
  second device is normally opened.
- A 2-minute background poll pulls only (local edits are already pushed by the
  mutation watcher, so pushing again would just double the traffic).
- The header indicator and a new "sync now" button in Settings call syncNow().

Also hardened push: rows owned by a different account are now skipped. On a
device shared between coaches, sending another account's rows violated RLS and
failed the entire table, taking this coach's own rows down with it.
